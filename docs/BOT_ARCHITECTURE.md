| File | Namespace | Responsibility |

## Per-turn control flow

The toolkit calls `run()` once per dragon per turn.

```
run()
  └─ Brain::think()
       ├─ updateView()         // fold the 7×7 view into per-tile memory
       ├─ updateKnowledge()    // learn new edges, portals, spawn timers
       ├─ receiveMessages()    // decode sonar pings from allies
       ├─ tryStrike()          // 1. head trade worth taking?
       │     └─ yes → sprint/move + return
       ├─ trySurvive()         // 2. every cardinal move is fatal → split
       │     └─ yes → split + return
       ├─ tryFeed()            // 3. feeder sacrifices itself for the king
       │     └─ yes → split-1 / move + return
       ├─ trySwarmSplit()      // 4. swarm phase: split in half
       │     └─ yes → split + return
       └─ bestMove()           // 5. score all legal moves, pick the best
             ├─ scoreMove() × 4
             └─ move + sendMessages()
```

All decisions are made in order. The first branch that fires wins; later branches are never evaluated.

## Data structures

### `Brain` (main.cpp)

One `Brain` per dragon per turn. All state is stored in `Brain` or in globals initialised from it.

```cpp
struct Brain {
    Controller& ct;        // toolkit handle (actions)
    Game& game;            // toolkit handle (observations)
    int myId;              // dragon id (stable across turns)
    char myTeam;           // 'A' or 'B'
    std::mt19937 rng;      // seeded with myId

    // ---- Persistent per-tile memory (W*H vectors) ----
    std::vector<int>     lastSeen;    // last round this tile was in view
    std::vector<int>     nextSpawn;   // our best estimate of the next pearl tick
    std::vector<int>     visitRound;  // last round our head stood here
    std::vector<double>  visitHeat;   // exponential recency+frequency (loop-break penalty)
    std::vector<uint8_t> pearlSeen;   // 1 if we have ever seen this tile

    // ---- This turn's view (populated by updateView) ----
    std::vector<uint8_t> inView;      // 1 if the tile is in the 7×7 window
    std::vector<uint8_t> pearlNow;    // 1 if a pearl is here this turn
    std::vector<int>     occId;       // dragon id on the tile (-1 = empty)
    std::vector<char>    occTeam;     // team of dragon occupying the tile
    std::vector<uint8_t> occHead;     // 1 if the occupying dragon's head is here
    std::vector<int8_t>  occDir;      // heading of the head (0–3 = NESW)
    std::vector<int>     bodyAge;     // turns until this body tile is vacated

    // ---- King tracking ----
    sonar::King bestKing;             // best KING message received or observed
    sonar::Enemy bestEnemy;           // best ENEMY message received or observed

    // ... plus cached flood-fill buffers, BFS queues, etc.
};
```

> [!NOTE]
> There is no cross-dragon shared memory. All coordination happens through sonar pings. Each dragon independently maintains its own copy of the per-tile state.

### Board globals (`board.hpp`)

```cpp
int W, H, N;              // board width, height, tile count

// Edge kinds per tile side: EK_OPEN, EK_KELP, EK_PORTAL, EK_UNKNOWN
std::vector<int8_t> hKind;   // north edge of tile t
std::vector<int8_t> vKind;   // west edge of tile t

// Portal destination: hPid[t] = tile on the other side of tile t's north portal
std::vector<int> hPid, vPid;

// Pearl spawn rates: minGap[t] and maxGap[t] (from the map file)
std::vector<int16_t> minGap, maxGap;
```

**Step resolution** — `bc::step(tile, dir)` returns:
- the destination tile index, or
- `STEP_KELP` (-1) if the edge is kelp, or
- `STEP_UNKNOWN_PORTAL` (-2) if the portal target is not yet known.

## Map knowledge system

### Embedded maps

`tools/gen_maps.py` reads every `.map` file in `maps/` and writes `maps_data.hpp`:

```cpp
namespace maps_data {
    inline const char* const NAMES[] = { "arena", "autarky", ... };
    inline const char* const MAPS[]  = { R"MAP(...)MAP", ... };
    inline constexpr int MAP_COUNT   = 15;
}
```

Each string is the raw map file text, stripped of comments and blank lines.

### Map matching (first turn)

On its first turn, each dragon:

1. Reads its 7×7 view to get the board width, height, and visible edge/portal layout.
2. For each of the 15 embedded maps with matching dimensions, parses the map and counts:
   - **wall mismatches:** visible edges that disagree with the stored map.
   - **portal mismatches:** visible portal destinations that disagree.
   - **spawn mismatches:** visible tiles whose `[minGap, maxGap]` disagrees with memory.
3. Accepts the first map where wall and portal mismatches are 0 and spawn mismatches ≤ `SPAWN_MISMATCH_OK` (default 3).
4. On success: copies the full wall, portal, and spawn-rate arrays into the board globals. The dragon now has global knowledge even of tiles outside its current 7×7 window.

If no map matches, the bot falls back to learning edges from whatever it sees each turn (`EK_UNKNOWN → EK_OPEN / EK_KELP / EK_PORTAL`).

### Symmetry and pearl timer mirroring

Each map declares a symmetry: `'h'` (mirror x), `'v'` (mirror y), `'r'` (rotate 180°). When a pearl appears at tile `t`, its timer is immediately copied to the mirror tile `t'`. This halves the information needed to track the full board.

## Pearl belief model

Each tile has a **belief** `b[t] ∈ [0,1]`: our estimated probability that a pearl will be present when we arrive at step `d`.

### Computation

```
If a pearl was just seen on tile t:
    nextSpawn[t] = round + minGap[t]           // earliest next spawn
    b[t] = 1 / (maxGap[t] - minGap[t] + 1)    // flat prior over the gap window

Else if nextSpawn[t] is known and round >= nextSpawn[t]:
    b[t] = (round - nextSpawn[t] + 1)
           / (maxGap[t] - minGap[t] + 1)       // linearly increasing chance

Else if tile has been seen but no timer (pearl not expected yet):
    b[t] = 0

Else (tile unseen):
    b[t] = UNSEEN_PRIOR * (avgSpawnRate)        // scaled prior
```

### Distance discounting

Belief at distance `d` is discounted:

```
b_discounted(t, d) = b[t] * GAMMA_BEST ^ d
```

### Competition discounting

```
If an enemy dragon reaches t first (by BFS from enemy heads):
    b[t] *= ENEMY_CLOSER    // default 0.15 — enemy will eat it

If an ally dragon reaches t first:
    b[t] *= ALLY_CLOSER     // default 0.25 — ally eats it, but it's a tie on our team
```

Ties (both reach at the same step) go to us — we are on the move.

### Remembered pearls

Pearls seen but not yet eaten are carried in memory and decay each round:

```
rememberedBelief[t] *= REMEMBERED_DECAY    // default 0.97 per round
```

## Safety — timed flood fill

Before committing any move, the bot checks whether it's safe by running a **timed BFS** from the destination tile.

### Body clearance timing

For every body tile in view, the bot knows exactly when it will be vacated (the tail advances one tile per turn):

```
bodyAge[t] = distance from that segment to the tail
// tile t is free at round (now + bodyAge[t])
```

This lets the BFS propagate through body tiles at the correct time.

### Safe-move condition

A move is **safe** if the BFS from the destination can reach our own freed body — i.e., there is a path that keeps ahead of our tail indefinitely. Formally: the fill finds a tile `t` in our body where `BFS_arrival_time(t) < bodyAge[t]`, meaning we get there before our tail leaves, and the path continues.

A fallback: if the accessible Voronoi room exceeds a threshold (`ROOM_THRESHOLD` tiles), the move is also accepted even without following the tail. This handles wide-open maps where the fill would take too long.

### Endgame king safety

From `CONSOLIDATE_ROUND` onward, the king dragon (`length ≥ KING_ROOM_LEN`) judges **escape splits** by the longest surviving piece, not total sum. This prevents a 24-long king from splitting in half to escape a temporary trap, leaving only two 12-long pieces.

## Move scoring

For each of the ≤4 legal moves, `scoreMove()` computes a scalar:

```
score = EAT_NOW     * pearl_at_dest_this_turn
      + FOOD_BEST   * GAMMA_BEST^d_best  * b[best_target]
      + FOOD_SUM    * Σ GAMMA^d_i * b[i]        // local richness
      - TRAPPED     * (not safe)
      + KING_ROOM   * voronoi_tiles              // dragons ≥10 long
      - THREAT_PER_LEN * max(0, enemy_len - my_len)  // enemy-forced trade
      - THREAT_EVEN * (enemy_can_force_even_trade)
      + HUNT_ATTRACT * steps_closer_to_target_enemy
      + FEED_PULL   * steps_closer_to_king       // consolidation phase
      - REVISIT     * visitHeat[dest]            // loop-break
      + SEAL_BONUS  * trapped_enemy_segments     // pocketing an enemy
      + STEAL_BONUS * b[near_enemy_head]         // starving their king
```

All weights are `params::` constants. The highest-scoring legal move is chosen.

## Decision pipeline

### 1. Strike (`tryStrike`)

Builds a BFS from each visible enemy head. For every enemy within `STRIKE_MAX_STEPS` sprint steps:
- Checks if the trade is favourable: enemy length > our length, or in aggressive mode.
- Plans a sprint path (1–`L-1` paid steps after the free steps).
- Executes the first step if the whole path is safe and the trade is good.

Aggressive mode: our visible heads / their visible heads ≥ `AGGRO_RATIO`.

### 2. Survive (`trySurvive`)

If all 4 cardinal moves lead to unsafe or fatal cells:
- Tries a range of split sizes: `length/2`, `length/2 ± 1`, bud of 2, reversal (child = `length - 2`).
- For each, checks if the parent's remaining piece and the child's piece are both safe after the split.
- Commits the split that maximises total surviving length.

### 3. Feed (`tryFeed`)

Active from `CONSOLIDATE_ROUND`. A dragon feeds if:
- It is within `FEED_DIST` BFS steps of a known king's last position.
- The king is longer by at least `FEED_KING_RATIO` × our length.
- Our length ≤ `FEED_MAX_LEN`.

The feeder moves adjacent to the king's head, then executes `SPLIT 1` (dies, dropping all segments as pearls). The king eats them next turn.

### 4. Swarm split (`trySwarmSplit`)

Before `CONSOLIDATE_ROUND`, if `length ≥ SWARM_SPLIT_LEN`:
- Checks that neither the parent nor the child would be trapped after the split.
- If `CHAIN_SPLIT`: also counts a child of 4+ that would immediately split again.
- Executes the split if safe; both halves continue independently.

### 5. Best move (`bestMove`)

Scores all legal moves using `scoreMove()` and picks the highest. Sends sonar messages after moving.

## Swarm and consolidation phases

| Phase | Rounds | Behaviour |
|---|---|---|
| **Swarm** | 0 → `CONSOLIDATE_ROUND` | Split at length 4; maximise dragon count; cheap head trades |
| **Transition** | `KING_GROW_ROUND` → `CONSOLIDATE_ROUND` | King stops splitting, accumulates length |
| **Consolidation** | `CONSOLIDATE_ROUND` → `KING_PULL_ROUND` | Small dragons navigate toward the known king |
| **Feed** | `KING_PULL_ROUND` → `FINAL_MERGE_ROUND` | Small dragons feed by dying next to the king |
| **Final** | `FINAL_MERGE_ROUND` → 500 | All remaining feeders sacrifice; king maximises length |

The king is identified by the KING sonar relay — the longest dragon the team is aware of. Each dragon that sees a dragon longer than `bestKing.len` updates its `bestKing` record and re-broadcasts it.

## Sonar system

Sonar pings are 64 bits, sent in one of four cardinal directions, received by the first dragon in that line (ally or enemy). To prevent enemies from forging or reading messages:

```
bits  0– 2  type (BODY=1, KING=2, ENEMY=3)
bits  3–11  check = mix(KEY ^ (type << 56) ^ payload) & 0x1FF   (9-bit keyed hash)
bits 12–63  payload XOR mix(KEY + type)                          (scrambled with key)
```

`KEY = 0xA11C0DEDB0A7F00D`. Enemies will fail the check with 2^9 = 1/512 false-positive rate; we always ignore failed checks.

### BODY message

Sent by the parent in the **split direction** on the split turn. The child receives it on its first turn via the sonar sent in the opposite heading (the parent's opposite direction = the child's tail direction).

Payload: 5-bit length + 2 bits/link for up to 24 segments. The child reconstructs its full body shape from this, avoiding a blind first turn.

### KING message

Payload (`sonar::King`):

| Bits | Field | Range |
|---|---|---|
| 0–11 | dragon id | 0–4095 |
| 12–19 | length | 0–255 |
| 20–26 | x | 0–127 |
| 27–33 | y | 0–127 |
| 34–42 | round | 0–511 |
| 43–50 | enemyMax (longest enemy seen) | 0–255 |

Relayed every turn by any dragon that knows a king position. A record is stale after `KING_STALE = 30` rounds without refresh.

### ENEMY message

Same layout as KING minus `enemyMax`. Relayed to pull small hunters toward the longest known enemy.

## Performance budget

The judge gives each dragon **100M "CPU points"** per turn, priced at approximately:
- 1 CPU point per simple arithmetic instruction.
- Higher for memory accesses (cache miss penalties apply).

AllRed's typical budget usage:

| Component | ~CPU pts |
|---|---|
| `updateView()` and board sync | 500K |
| Map matching (first turn only) | 2M |
| BFS for enemy reach | 2–5M |
| Timed flood fill × 4 moves | 10–25M |
| `scoreMove()` × 4 | 2M |
| Strike planning | 3–8M |
| **Total typical** | **20–45M** |

Worst-case observed on large maps (64×64): **~87M** before the CPU guard was added. The guard limits BFS and flood fill depth on boards > 1000 tiles.

> [!CAUTION]
> `params::DEBUG = true` prints move scores every turn. On the judge, every byte of output costs CPU points. Always turn debug off before submitting.
